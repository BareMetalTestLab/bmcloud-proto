# bmcloud-proto

The protobuf contract for the bmcloud device channel — the WSS protocol
between the stand (or the PC agent) and the bmcloud server.

Single source of truth for both ends:

- server / PC agent (Rust): generated by `prost-build` from
  `proto/bmcloud/*.proto`;
- stand firmware (C, esp-idf): generated by `nanopb` from the same files,
  bounded by `nanopb.options`.

One WSS binary frame = exactly one encoded envelope: `DeviceMessage` from the
stand, `ServerMessage` from the server. Control frames (capabilities,
heartbeat, jobs, acks) always overtake bulk transfer chunks in the send
queue — on both ends.

## Layout

```
proto/bmcloud/device.proto   # envelopes, capabilities, heartbeat, jobs, transfers
proto/bmcloud/streams.proto  # peripheral IO: StreamData, CanFrame, Event, open/close
nanopb.options               # MCU field limits; Rust builds ignore it
```

Both files share `package bmcloud`: one namespace on the wire and in every
generator, the split is authoring convenience only.

## Consuming

Rust (prost), in `build.rs`:

```rust
prost_build::compile_protos(
    &[
        "../bmcloud-proto/proto/bmcloud/device.proto",
        "../bmcloud-proto/proto/bmcloud/streams.proto",
    ],
    &["../bmcloud-proto/proto"],
)?;
```

esp-idf (nanopb): add nanopb as a component, generate in the build
(CMake custom command) with `--options-file nanopb.options`, commit neither
the generated `.pb.c` nor the Rust types — both sides build them.

## Rules

1. Pin a release tag (`vX.Y.Z`) in the consumer's submodule; never track
   a branch.
2. Never reuse a field number; removed fields become `reserved`.
3. Breaking change (renumbering, type change) bumps the major version; new
   optional fields bump the minor.
4. Every message the stand must decode has bounds in `nanopb.options`;
   adding a variable-size field means adding its bound in the same commit.
5. Event `kind` values are documented here when introduced:
   - `registers` — Cortex-M core registers at a hardfault, R0–R15, xPSR,
     SP, PC plus a stack fragment, packed little-endian u32s;
     the exact layout is owned by the stand firmware version that emits it.
   - `reset_reason` — a u32 reset-cause register plus a source id.
   - `coredump` — travels as an artifact transfer, not as an Event payload.

## Planned additions

Stage 3 adds the upload direction: `TransferBegin` / `TransferChunk` /
`TransferEnd` join `DeviceMessage` (the stand sends core dumps and artifacts),
and `TransferAck` joins `ServerMessage` (the server acks uploads).
`TransferBegin` gains a `purpose` field so the receiver can route blobs
(firmware, artifact kinds). Adding oneof variants and optional fields is
wire-compatible — a minor version bump, not a breaking change.
